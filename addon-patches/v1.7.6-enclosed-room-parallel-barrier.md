# Addon V1.7.6 — Enclosed Room + Hit-Face Parallel Barrier

Baseline: Addon V1.7.5

Target: Addon V1.7.6

Bot remains V1.7.5. Protocol remains V3.

## Why V1.7.6 exists

V1.7.5 could misclassify a real 6×6 wall as passable. Two causes were identified:

1. Barrier width axis was guessed from the player-to-player ray direction instead of using the block face actually hit.
2. V1.7.5 short cell probes could start inside the collision volume of the cell being tested, so a full neighboring wall block could be reported as non-blocking.

V1.7.6 removes the inside-block cell-probe classifier and changes wall measurement to hit-face-aware parallel acoustic rays.

## Acoustic rule

For ordinary non-enclosing obstacles:

```text
BLOCK when
width >= ceil(Mic Range)
AND
height >= ceil(Mic Range)
```

For a fully sealed room:

```text
If A is inside a sealed acoustic component
and B is outside that same component
→ BLOCK regardless of room size versus Mic Range.
```

This gives Range 5 behavior:

```text
5×3 wall  -> PASS
5×4 wall  -> PASS
5×5 wall  -> BLOCK
6×6 wall  -> BLOCK
small fully sealed room -> BLOCK
small room without roof -> not treated as sealed
same sealed room + small pillar between A/B -> PASS if the pillar itself is below the barrier threshold
```

## Hit-face-aware parallel barrier scan

`BlockRaycastHit.face` determines the wall normal and width axis.

```text
East/West hit -> normal X, width Z
North/South hit -> normal Z, width X
```

The analyzer casts parallel rays by shifting the original A↔B segment along the width axis and Y. A shifted ray counts toward the same barrier only when its first hit has the same wall-normal block coordinate as the anchor hit.

This avoids accidentally measuring wall thickness instead of wall width when players stand diagonally to a wall.

Pseudo-flow:

```text
Head A→B and B→A raw rays
Chest A→B and B→A raw rays
        ↓
any symmetric direct path fully clear?
        ├─ yes -> PASS
        └─ no
             ↓
      sealed-room separation?
        ├─ yes -> BLOCK
        └─ no
             ↓
      hit-face parallel span scan
             ↓
      width >= R AND height >= R ?
        ├─ yes -> BLOCK
        └─ no  -> PASS
```

## Enclosed-room detector

The detector is intentionally bounded and only runs after both direct Head and Chest paths are obstructed.

It uses:

- 2D acoustic flood-fill at participant chest level instead of full 3D flood-fill.
- Collision-aware one-block ray transitions using `includePassableBlocks:false`.
- Radius `ceil(Range) + 1`.
- Safety node budget capped at 4096.
- After horizontal closure is found, every reachable column must have both a roof hit above and a floor hit below within the bounded vertical limit.
- If the component reaches the search boundary, exceeds the safety budget, has a skylight/open shaft, or lacks a floor, it is not claimed as a sealed room.
- Per-snapshot enclosure and transition caches are used so repeated player pairs do not redo the same work.

Large rooms that exceed the bounded enclosure search still fall back to normal wall-size blocking. This keeps the expensive enclosure rule focused on the important case: small rooms that are fully closed but smaller than the microphone range.
